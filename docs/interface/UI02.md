# UI-02 — attente, absence, refus et panne

État : réalisé et vérifié sur `direct/interface-etats`, publication en cours. Code éprouvé : `a69bd9d91a56b986ed1a3120b11f7e5267db202a`, basé sur UI-01 fusionné.
Le joueur peut distinguer une lecture en cours, une donnée absente, une demande refusée et une panne : chaque état porte un mot, un signe et une cause fournie. Aucun ordre ni appel réseau n’est déclenché par ces composants.
`EtatsLecture.Afficher` remplace tout ancien contenu ; un état inconnu ou une cause vide est refusé avant changement. `Mesure` conserve le zéro, le signe et la précision reçus, exige une unité, et déclare explicitement `null`. Le texte reçu ne peut pas injecter de mise en forme ; la hauteur suit son contenu (le dossier intégrateur devra prévoir son défilement).
Dans Unity 6000.0.43f1 : **Forge → Interface → Galerie des états** propose de sauvegarder la scène courante puis lance une scène isolée en Play. Quatre dossiers restent visibles simultanément ; arrêter Play pour revenir à l’éditeur.
Preuve du 15 octobre : les douze tests UI-02 échouent sur les composants vides, puis passent après implémentation ; les six tests UI-01 restent verts, soit dix-huit tests. Aucun test existant modifié.
[Rapports bruts rouge/vert et manifeste du projet de contrôle](preuves/UI02-a69bd9d.zip) ; [capture Unity réelle en Play](preuves/UI02-a69bd9d.png) sur le même code, regardée : quatre états lisibles, signes présents, causes entières à 1920 × 1080.
Reproduction isolée : copier `Assets/Interface` dans un projet Unity avec le manifeste de l’archive, puis `Unity.exe -batchmode -nographics -projectPath <projet> -runTests -testPlatform EditMode -testFilter Forge.Interface.Tests -testResults <resultats.xml>` ; ouvrir le menu pour examiner la galerie.
Comparaison aux références revues : papier/encre de `imprimerie_1600.png`, contraste sombre et accents limités de `forge_1450.png`. Les signes complètent les couleurs ; aucune texture ne gêne les motifs.
Limites : galerie de démonstration, causes illustratives, police Unity provisoire ; preuve dans un projet de contrôle isolé, sans transport réel ni parcours complet du jeu. L’adaptateur futur choisira l’état selon la réponse reçue ; aucun besoin supplémentaire de simulation n’est introduit ici.
